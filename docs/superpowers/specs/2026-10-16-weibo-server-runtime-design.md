# 微博超话签到服务器运行设计

## 目标与范围

让微博超话自动签到可在 Linux Docker 服务器上由后端定时执行。沿用当前账号管理和手动登录流程，登录态按账号隔离并持久保存。贴吧签到、微博发帖、回复、转发和浏览任务不纳入本次行为改造。

## 当前状态

项目已有 Spring Boot 定时任务、Playwright 浏览器容器和 Docker Compose 配置。微博适配器目前连接 `localhost:9222` 并复用第一个 Chrome context；在后端与浏览器分容器时该地址指向后端容器本身，也无法保证多个账号使用各自的登录态。账号页面的浏览器登录会话目前由后端本地启动浏览器，因此服务器容器也无法稳定提供该流程。

## 设计

- 后端通过可配置的 CDP 地址访问 Chromium worker；Compose 环境用服务名寻址，开发环境保留本机地址配置。
- 每个微博账号使用独立浏览器 context，加载该账号 `storage/profiles/{userId}/weibo/{accountId}/state.json` 中的登录态。签到和登录状态检查都使用同一账号 context，任务结束后关闭 context。
- 手动登录会话也在 Chromium worker 内建立；noVNC 继续提供浏览器交互界面，保存时将 context 的 storage state 写入共享持久卷。CDP 端口只在 Compose 内部网络供后端访问。
- 保留每日 08:20 的微博签到调度和现有签到 API。服务器时区明确设为 Asia/Shanghai。无需调整平台操作逻辑或增加账号凭据存储。

## 失败处理与验证

浏览器不可用、登录态过期或需要人工验证时，沿用现有失败结果和签到记录，不尝试绕过验证。验证重点为：Compose 中后端能连接 Chromium；多个账号的登录态互不混用；会话保存后重启仍可加载；微博签到手动入口与每日调度都调用远端浏览器。不得把真实 Cookie 或登录态写入日志或仓库。

## 部署影响

部署需要持久挂载共享的 storage 目录；浏览器容器提供 CDP 和 noVNC，后端通过 Docker 内网访问 CDP。使用浏览器登录时，管理员浏览器需能访问配置的 noVNC 地址。
